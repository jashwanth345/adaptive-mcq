LOCAL API · PHASE 4

Adaptive MCQ backend

Authentication, role checks and diagnostics are available. Dashboards, assessments and AI features are planned. This page loads entirely from this computer.

Process health

GET /api/v1/health/live returns 200 while the API is running. It does not confirm database or model readiness.

Database readiness

GET /api/v1/health/ready returns 200 when foundation checks pass, or 503 when setup is incomplete. Checks cover connectivity, pgvector, migration history and the runtime database role.

Response

Choose a check above.
A ready response confirms backend foundation only. It does not confirm that local LLMs are installed or that generation works.

Authentication

POST /api/v1/auth/register creates a student account. Send email, display_name and password as JSON. Teacher access is granted by a local operator.

POST /api/v1/auth/login accepts email and password. Use the returned access token as Authorization: Bearer <token>. Tokens expire after 15 minutes by default.

GET /api/v1/auth/me returns your profile and current roles. POST /api/v1/auth/logout ends the current session; /logout-all ends every session. /change-password takes current_password and new_password and ends all sessions.

No cookies, password reset email or refresh tokens are provided in this phase. Keep tokens private; this documentation page does not store them.

Role checks

GET /api/v1/roles/teacher and /api/v1/roles/student require the corresponding account role. These are access checks, not dashboards.

API contract

OpenAPI JSON describes the implemented routes. Errors include a safe message and request ID. A 401 means credentials/session are invalid; 403 means the role is missing; 429 means throttling; 503 means database setup needs attention.
