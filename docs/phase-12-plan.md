# Phase 12 — deterministic validation and release gates

Scope: free local mathematical validation, owner-scoped duplicate detection, saved validation evidence and fail-closed release prerequisites. Keep default test generation/review; no LLM weights, cloud services or inference. Teacher editing/approval UI remains Phase 13.

Math: bounded Python standard-library AST traversal and exact Fraction arithmetic, never eval/exec. Support only full stems `Calculate: <expression>` / `Evaluate: <expression>` and four numeric-expression options. Operators +, -, *, /, bounded integer ** and parentheses. Reject missing/incorrect keys, equivalent options, undefined operations and resource-limit violations. Unsupported word problems, units, rounding, variables, functions and symbolic algebra block readiness. Offer an explicitly unsaved arithmetic-check preview for demonstration; it cannot authorize release. No SymPy dependency is needed for this deliberately narrow arithmetic scope.

Duplicates: compare normalized stems with the latest versions of other questions owned by the same account; include exact matches and a conservative token-overlap heuristic. Cap at 2,000 candidate questions, mark larger scans incomplete and block readiness. Never expose another owner's question text. Persist the comparison corpus fingerprint; newly added/edited/archived questions invalidate it at release time. Semantic paraphrase detection remains future work.

Database: additive migration 005, immutable owner/version-scoped validation reports, private idempotency keys, narrow insert/read grants. Gate technical readiness on real generation provenance, current actual-AI verifier PASS with blind-key agreement, schema/source integrity, complete duplicate scan and supported math outcome. Reports never publish. Add database release/publication prerequisites for fresh validation evidence, current verifier evidence and owning teacher approval for classroom use. Preserve the blueprint's separately eligible automatic student-practice path and quarantine operations. No changes to historical migrations or fabricated verification scores.

API/UI: own draft validation create/history, arithmetic preview, saved checks/blockers and retry states within Draft studio. Input cannot override owner, verdict or release eligibility. No automatic release API. Explain structural checks separately from factual/educational correctness.

Verification: adversarial arithmetic fixtures, equivalent options, duplicate privacy/limits, stale-evidence gates, mock exclusions, wrong owner/version, idempotency/rollback, migration replay/upgrade, existing API regression, frontend build/tests and lightweight browser flow. Existing FREE / OPEN SOURCE dependencies only. Native PostgreSQL deployment and real-model hardware/quality validation remain pending.
